# 의존성 최신화 — 코드 의존성 · 번들 법령·고시 · 공식 양식 · 원본 주소

v1.8.4(`16139a3`) 기준 점검(2026-11-03)에서 확인된, 시간이 지나 낡은 부분을 현행으로 맞춘다.
버전 올림·CHANGELOG·태그·배포는 이 명세 범위 밖이다(반영 뒤 별도로 한다).

## 작업 1 — 코드 의존성 (CI 감사 단계 복구)

현황: `ci.yml` 의 `npm audit --audit-level=high` 가 현재 잠금 파일로 실패한다(운영 치명 1·높음 3, 개발 포함 13건).
잠금 파일 사본 재현: SDK 만 1.32.2 로 올리면 여전히 실패, 하위·개발 의존성까지 갱신해도 zod 높음 1건(수정판 4.6.6 이상만 존재)으로 실패, zod 4 까지 옮기면 통과.

- WHEN 의존성을 갱신할 때, SYSTEM SHALL `@modelcontextprotocol/sdk` 를 `^1.32.2` 로 올리고 취약한 하위·개발 의존성(proxy-addr·body-parser·kordoc·markdown-it·sharp·undici 등)을 수정판으로 갱신한다.
- SYSTEM SHALL zod 를 3.x 에서 4.x(4.6.6 이상)로 옮기고, 모든 도구의 입력 스키마가 옮기기 전과 같은 입력을 받고 같은 입력을 거부하게 한다(`z.record` 인자, 오류 메시지 옵션 등 4.x 변경점 대응).
- SYSTEM SHALL CI 매트릭스에 Node 24.x·26.x 를 더한다. `engines`(>=20.19.0)와 20.19.0 매트릭스는 이번에 바꾸지 않는다(지원 범위 축소는 별도 결정).
- 열린 의존성 갱신 PR(SDK 1.31.0 / 개발 의존성 묶음)은 이 변경으로 대체된다 — PR 을 닫는 일은 이 작업에 포함하지 않는다.

완료 기준
- [ ] `npm ci && npm audit --audit-level=high` exit 0 (개발 의존성 포함, CI 와 같은 명령)
- [ ] `npm run typecheck`, `npm test`, `npm run test:full` 통과
- [ ] MCP 서버가 도구 92개를 그대로 등록하고, 대표 도구(assemble_doc_context·generate_safety_document·review_safety_document·verify_safety_basis)가 옮기기 전과 같은 입력에서 같은 구조의 결과를 낸다(시험 또는 대조 기록)

## 작업 2 — 번들 법령·고시 · 공식 양식 · 원본 주소

법령 원문은 법제처 국가법령정보센터 기준으로 조회한다(korean-law MCP, 또는 `scripts/sync/sync-articles-from-moleg.ts` + `LAW_OC`). 산업안전보건법은 시행예정본이 섞이므로 시행일(efYd)을 지정해 조회한다.

### 2-1. 산업안전보건법 2026-10-27 개정 (법률 제22122호, 공포·시행 2026-10-27, MST 291447)
- 번들 `src/ontology/safety-laws/README.md`·`산업안전보건법.md` 머리말의 현행 표기를 제21374호 → 제22122호로 고치고, 시행예정 일정을 현행으로 적는다: 2026-12-08(타법개정) · 2027-01-01 · 2027-01-08 · 2027-01-28 · 2027-04-28 · 2027-10-28(산업안전보건법), 2027-01-01(시행령).
- 이미 시행 중인 변경을 그래프 조문 노드에 반영한다: 제70조 ①1호("태풍ㆍ홍수ㆍ폭염ㆍ한파 등 악천후"), 제84조 ②1호("연구ㆍ개발 또는 수출을 목적으로 제조하거나 수입하는 경우"). 시행 전 변경(제51조·제55조·제72조 등)은 현행 문구를 유지하고 시행일만 기록한다.
- 번들 `산업안전보건법.md` 13개 조문 본문을 현행(2026-10-27 시행본)과 글자 단위로 대조한다.

### 2-2. 조문 노드 판본 정합
- 산업안전보건법·시행령·시행규칙·안전보건규칙 조문 노드 전체를 현행 판과 대조한다. 본문이 같으면 판본 표지(`_meta.lawServiceMST`·검증일)만 현행으로, 다르면 본문을 현행 원문으로 바꾼다.
- 대조를 통과한 노드는 `needsVerification` 을 내리고 본문 출처 표지(`bodySource`)를 실제 출처로 고친다. 표지끼리 어긋난 노드(`verified` 인데 `needsVerification: true`)가 남지 않게 한다.
- 대조 결과(조문별 같음/교체/조회 실패)를 기록 파일로 남긴다.

### 2-3. 판본 점검을 날짜가 아닌 판본 비교로
- 번들 법령의 판본(MST)을 법제처 현행 판·시행예정과 비교하는 점검 스크립트와 npm 스크립트를 더한다(`LAW_OC` 가 없으면 건너뛴다고 분명히 출력).
- `inspect` 의 법령 동기화 줄은 날짜만 본다는 사실을 출력에 밝히고, 판본 점검 명령을 안내한다.

### 2-4. 산업안전보건관리비 고시
- 인용을 "고시 제2022-43호" → 현행 "건설업 산업안전보건관리비 계상 및 사용기준"(고용노동부 고시 제2025-11호, 2025-02-12 시행)으로 고친다(의무 마스터 scope·관리비 사용계획서 노드 등 전부).
- 두 판의 내용(계상 요율·사용 항목·사용기준)을 대조해, 코드·데이터에 담긴 값이 현행과 다르면 고친다. 대조 결과를 기록한다.

### 2-5. 산업재해조사표 (시행규칙 별지 제30호서식, <개정 2025. 10. 1.>)
- 번들 원본 hwp 를 현행 서식으로 바꾸고 양식 지도(`forms-map.json`) 항목(파일·크기·출처)을 고친다.
- 문서 노드·자동 생성 양식을 현행 칸에 맞춘다: 재해자 주민등록번호는 **앞 7자리**만(외국인등록번호), 재해자 주소·휴대전화, 산재보험급여 신청방법 안내를 위한 개인정보 활용 동의 칸, "통계청" → "국가데이터처". 현행 서식에 없는 성별 칸은 뺀다. 입력 안내의 "주민등록번호 13자리"를 고친다.
- 옛 입력 키를 넘긴 호출이 오류로 끝나지 않게 한다(무시하거나 새 키로 옮김 — 어느 쪽인지 기록).

### 2-6. 응답하지 않는 양식 원본 주소
- `kras.kosha.or.kr`(접속 거부) → 현행 KRAS 위치(`portal.kosha.or.kr/kras/...`)의 해당 페이지로. 이 주소를 쓰는 노드·문서 전부.
- KOSHA 밀폐공간 기술지침(404), KOSHA 전자책 내려받기 2개(500)는 현행 공식 주소를 찾아 바꾼다. 찾지 못하면 그 사실을 기록하고, 사용자에게 내려받기 주소로 보이지 않게 한다.
